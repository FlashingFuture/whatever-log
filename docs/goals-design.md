# 목표와 연결 프로세스 (packages/goals)

사용자가 "하루에 공부 2시간" 같은 목표를 만들고, 그 목표에 **연결할 프로세스**(예: `Code.exe`)를 고르면,
그 프로세스들의 활성 시간 합이 목표의 달성 시간이 된다. 크롬·엣지 같은 브라우저는 프로세스 전체뿐 아니라
**사이트(세부 페이지)** 단위로도 연결할 수 있다. 이 문서는 그 데이터를 어디서 어떻게 다루는지
(책임, 저장, 엄격한 입력 규칙)를 정리한다. 서버로 무엇이 나가는지는 `docs/data-handling.md`가 기준이다.

## 책임: 화면이 아니라 패키지

| 맡은 곳 | 하는 일 |
| --- | --- |
| `packages/goals` | 목표가 무엇인지, 무엇이 올바른 입력인지(검증), 저장(`goals.db`), 하루 스냅샷 — **규칙의 유일한 원본** |
| `apps/hub` (예정) | `/api/goals` CRUD로 노출. 쓰기 엔드포인트라 허용된 Origin·JSON 본문만 받는다 |
| `apps/ui` (예정) | 입력 폼과 프로세스 고르기. 규칙을 다시 구현하지 않고 서버의 검증 오류를 그대로 보여 준다 |
| 전송 에이전트 (예정) | UI 없이도(창이 닫혀 있어도) 같은 패키지로 목표를 읽어 달성 수치를 서버로 보낸다 |

패키지로 둔 이유: 전송은 UI가 닫혀 있을 때도 돼야 하고, 화면·전송·메일이 **같은 정의**의 목표를 써야
하기 때문이다.

**무엇이 PC 밖으로 나가는지**(기준은 `docs/data-handling.md`): 목표 설정 전체는 `goals.db`에 이 PC에만
저장된다. 그중 **어떤 프로세스가 어느 목표에 속하는지(연결 프로세스)는 서버로 보내지 않는다.** 보고서를
요청할 때 서버로 가는 것은 마스킹·집계한 값 — 기간, 목표 이름, 설정 목표량, 달성 시간, 달성률뿐이다(예정).

## 저장

- 저장 타입까지 제약으로 지킨다: 숫자 칸(`daily_target_minutes`, `weekdays`)은 `typeof = 'integer'`와 범위를
  함께 `CHECK`한다. SQLite는 INTEGER 열에 `1.5`가 들어오면 REAL로 그대로 보관해 범위 검사만으로는
  통과하기 때문이다.

- 파일은 `goals.db`(SQLite, WAL)다. `recorder.db`와 나눈 이유: 그 파일은 recorder만 쓰고 hub는 읽기만
  하는데, 목표는 hub와 전송 에이전트가 쓰기도 하는 사용자 설정이라 쓰기 주체가 섞이지 않게 한다.
  쓰기는 `BEGIN IMMEDIATE`로 직렬화한다. 파일의 `user_version`이 이 코드보다 새로우면 연결을 거부한다.
- 연결 대상은 `{종류, 이름}`으로 저장한다. 종류는 `process`(`이름.exe`)와 `site`(`브라우저/도메인`)이고,
  `CHECK`로 허용 목록을 닫아 모르는 종류가 못 들어온다. 사이트는 브라우저별로 사용 시간이 따로 집계되므로
  브라우저와 도메인을 `/`로 합쳐 한 칸에 저장한다(둘 다 `/`를 가질 수 없어 모호하지 않다). 그래서 `UNIQUE (kind,
  name_key)` 하나로 "한 대상은 한 목표에만"이 사이트에도 적용된다. 스키마 버전은 2이고, 1(프로세스만)의
  파일은 열 때 대상 테이블을 새 `CHECK`로 다시 만들어 올린다.

## 엄격한 입력 규칙

목적이 분명하다(이름 + 하루 목표 시간 + 요일 + 프로세스 이름)는 점을 이용해, 조금이라도 다르면 조용히
고쳐 받지 않고 **거부한다**. 모든 칸의 오류를 한꺼번에 돌려준다(`GoalValidationError.errors`) — 형식
오류뿐 아니라 다른 목표와의 충돌(같은 이름, 이미 연결된 프로세스)도 같이 알려, 사용자가 한 번에 고칠 수 있다.

| 칸 | 규칙 |
| --- | --- |
| 이름 | 문자열, 1~50자, 앞뒤 공백·제어 문자(줄바꿈·탭·폭 없는 공백) 금지. 유니코드 NFC로만 정규화(유일한 자동 수정). 대소문자·표현 차이를 무시하고 중복 금지 |
| 하루 목표 시간 | 정수(분)만. 문자열·실수·`true`는 거부. 1~1440 |
| 요일 | 목록(월=0 … 일=6), 비어 있지 않고 중복 없음. 집합·문자열은 거부 |
| 연결 프로세스 | 0~20개(목표를 먼저 만들고 나중에 연결할 수 있다), 각각 올바른 `*.exe` 파일 이름(Windows 파일 이름에 못 쓰는 글자·제어 문자·앞뒤 공백·예약 이름(`CON`, `NUL`, `COM1`…) 금지, **255 UTF-16 코드 단위** 이하 — 이모지 같은 글자는 두 단위를 차지한다). 대소문자 무시 중복 금지. `.tmp` 같은 설치 도구 프로세스는 연결 대상이 아니다 |
| 연결 사이트 | 0~20개, 각각 `{browser, domain}` 두 칸만 있는 객체. `browser`는 프로세스 이름 규칙을 따르고, `domain`은 recorder가 기록하는 모양(소문자, 앞의 `www.`·앞뒤 점·공백·`/\?#@%[]` 없음, 253자 이하)이어야 한다. 중복 금지(브라우저 이름은 대소문자 무시) |
| 기록 여부 | 호출부(hub)가 기록된 프로세스·사이트(브라우저, 도메인) 목록과 지원하는 브라우저 목록을 주면, 그 목록에 **정확히** 있는 것만 받는다(기록된 적 없는 이름을 연결해 달성률이 영원히 0이 되는 일 방지) |
| 개수 | 목표는 20개까지 |
| 수정 | 통째로 교체(PUT). 일부 칸만 바꾸는 입력은 받지 않는다 |

**한 프로세스는 하나의 목표에만** 연결된다. 같은 프로세스가 두 목표에 있으면 같은 활성 시간이 두 번
세어져 총합이 부풀려지기 때문이다. 검증이 먼저 막고, `UNIQUE (kind, name_key)` 제약이 마지막 방어선이다.
비교 키는 `casefold`라서 `Code.exe`와 `code.exe`는 같은 프로세스다(Windows 파일 이름은 대소문자를 구분하지
않는다).

**브라우저 전체와 그 안의 사이트는 함께 연결할 수 없다.** 크롬 전체의 시간에는 그 안의 사이트 시간이 이미
들어 있어 같이 연결하면 두 번 세어지기 때문이다. 같은 목표 안에서는 사이트 쪽(`overlaps_process`), 다른 목표와는
프로세스 쪽(`overlaps_site`)·사이트 쪽 오류로 알린다. 같은 도메인도 브라우저가 다르면(크롬의 `youtube.com`과
엣지의 `youtube.com`) 다른 대상이다.

## 하루 스냅샷

목표를 나중에 바꿔도 **지난 날의 달성률이 바뀌지 않게** 날짜별로 그날의 설정(이름, 목표 시간, 연결
프로세스)을 기록한다. 규칙은 단순하다.

- `snapshot_today(today)`가 그날 요일에 적용되는 목표만 현재 설정으로 기록하고, 오늘 안에서는 목표를
  고칠 때마다 다시 호출해 덮어쓴다.
- 날짜가 지나면 확정된다: 이미 기록된 가장 늦은 날짜보다 이른 날짜는 거부해, 호출부가 지난 날짜를
  잘못 넘겨도 확정된 기록이 덮어써지지 않는다. 시계의 UTC 날짜와 하루를 넘게 차이 나는 날짜도 거부한다
  (어느 시간대의 "오늘"이든 UTC 날짜의 앞뒤 하루 안쪽이다).
- 목표를 삭제해도 지난 스냅샷은 남는다(`goal_id`는 목표 테이블에 묶지 않는다).
- "오늘"은 호출부가 **로컬 시간대**로 정해 넘긴다 — 이 패키지는 시간대를 모른다(`period`와 같은 원칙).

## 수행 시간 (`compute_progress`)

목표의 수행 시간은 **연결된 프로세스와 사이트의 활성(active) 시간 합**이다(유휴·백그라운드 제외, 프로세스
이름은 대소문자 무시, 요일 배수 없음). 사이트의 시간은 그 브라우저가 foreground였던 시간 중 그 도메인에 쓴
시간(`site_usage_by_range`)이다. 정의는 이 패키지(`progress.py`) 한 곳에 있고 hub는 사용량 합계를 넘겨
호출만 한다. 홈 요약의 "목표 중 가장 길게 수행한 프로세스"도 여기서 나오며(동률은 이름 순, 후보는 연결한
프로세스와 사이트 모두 — 사이트면 `site`에 도메인이 있고 `process`는 그 브라우저다), 화면은 이를 실제 최장
프로세스와 비교해 같으면 하나로 합친다. 사이트는 브라우저의 일부라 그 브라우저 전체와는 같은 것으로 합치지 않는다.

## hub API와 보호

- `GET /api/goals`, `POST /api/goals`(201), `PUT /api/goals/<id>`, `DELETE /api/goals/<id>`(204),
  `GET /api/goals/progress?start&end`, `GET /api/processes`(추적된 프로세스, 유효한 이름만), `GET /api/tracked-sites`(추적된 브라우저 사이트
  `{browser, domain}`, 지원하는 브라우저·유효한 도메인만). 목표 본문은 `name`, `daily_target_minutes`, `weekdays`,
  `processes`, `sites` 다섯 칸이 모두 필요하다.
- 오류는 `{"error":{"code","message","fields?"}}` — 입력 오류는 칸별(`fields`)로 돌려준다.
- 쓰기(POST/PUT/DELETE)는 Host가 로컬이고, Origin이 허용 목록(`127.0.0.1`/`localhost`)이며,
  `Content-Type: application/json`, 본문 32KB 이하, 모르는 필드 없음일 때만 받는다(CSRF·DNS 리바인딩 방어).
  본문이 `Content-Length`보다 짧거나 JSON이 아니거나 너무 깊게 중첩돼도 400이다. `DELETE`는 반대로 본문이나
  `Content-Type`이 있으면 400으로 거부한다. 요청을 읽는 소켓에는 15초 제한 시간이 있다. 연결할 프로세스·사이트가
  없는 목표는 기록 DB를 읽지 않고 저장한다.
  CORS preflight는 허용된 Origin에만 응답한다.

## UI

홈 왼쪽 요약은 목표 수행 시간과 가장 길게 수행한 프로세스(목표 중 / 실제, 같으면 하나), 그 아래 파란
"목표 프로세스 관리" 링크다. 링크는 모달을 연다: 목록(+ 만들기) → 목표를 누르면 연결 프로세스 관리
(클릭 또는 드래그앤드롭으로 바로 저장), 수정·삭제 아이콘은 hover·포커스·우클릭 때 나타난다. 크롬·엣지 같은 브라우저 행에는 "사이트 N개"
펼치기가 있어 세부 페이지(도메인) 단위로도 클릭·드래그로 연결한다. 사이트가 연결된 브라우저는 전체 추가가
비활성이고(이유를 툴팁으로 알린다), 다른 목표에 연결된 프로세스·사이트는 목표 이름과 함께 흐리게만 보인다. 이름 앞뒤
공백 제거 외의 검증은 모두 서버 몫이다.
