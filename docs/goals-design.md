# 목표와 연결 프로세스 (packages/goals)

사용자가 "하루에 공부 2시간" 같은 목표를 만들고, 그 목표에 **연결할 프로세스**(예: `Code.exe`)를 고르면,
그 프로세스들의 활성 시간 합이 목표의 달성 시간이 된다. 이 문서는 그 데이터를 어디서 어떻게 다루는지
(책임, 저장, 엄격한 입력 규칙)를 정리한다. 서버로 무엇이 나가는지는 `docs/data-handling.md`가 기준이다.

## 책임: 화면이 아니라 패키지

| 맡은 곳 | 하는 일 |
| --- | --- |
| `packages/goals` | 목표가 무엇인지, 무엇이 올바른 입력인지(검증), 저장(`goals.db`), 하루 스냅샷 — **규칙의 유일한 원본** |
| `apps/hub` (예정) | `/api/goals` CRUD로 노출. 쓰기 엔드포인트라 허용된 Origin·JSON 본문만 받는다 |
| `apps/ui` (예정) | 입력 폼과 프로세스 고르기. 규칙을 다시 구현하지 않고 서버의 검증 오류를 그대로 보여 준다 |
| 전송 에이전트 (예정) | UI 없이도(창이 닫혀 있어도) 같은 패키지로 목표를 읽어 달성 수치를 서버로 보낸다 |

패키지로 둔 이유: 전송은 UI가 닫혀 있을 때도 돼야 하고, 화면·전송·메일이 **같은 정의**의 목표를 써야
하기 때문이다. 목표 설정(이름, 연결 프로세스)은 이 PC에만 있고 서버로 보내지 않는다.

## 저장

- 파일은 `goals.db`(SQLite, WAL)다. `recorder.db`와 나눈 이유: 그 파일은 recorder만 쓰고 hub는 읽기만
  하는데, 목표는 hub와 전송 에이전트가 쓰기도 하는 사용자 설정이라 쓰기 주체가 섞이지 않게 한다.
  쓰기는 `BEGIN IMMEDIATE`로 직렬화한다. 파일의 `user_version`이 이 코드보다 새로우면 연결을 거부한다.
- 연결 대상은 `{종류, 이름}`으로 저장한다(지금 종류는 `process`뿐이다). 나중에 사이트 등을 더해도 저장
  구조가 바뀌지 않게 종류 칸을 두되, `CHECK`로 허용 목록을 닫아 모르는 종류가 못 들어온다.

## 엄격한 입력 규칙

목적이 분명하다(이름 + 하루 목표 시간 + 요일 + 프로세스 이름)는 점을 이용해, 조금이라도 다르면 조용히
고쳐 받지 않고 **거부한다**. 모든 칸의 오류를 한꺼번에 돌려준다(`GoalValidationError.errors`).

| 칸 | 규칙 |
| --- | --- |
| 이름 | 문자열, 1~50자, 앞뒤 공백·제어 문자(줄바꿈·탭·폭 없는 공백) 금지. 유니코드 NFC로만 정규화(유일한 자동 수정). 대소문자·표현 차이를 무시하고 중복 금지 |
| 하루 목표 시간 | 정수(분)만. 문자열·실수·`true`는 거부. 1~1440 |
| 요일 | 목록(월=0 … 일=6), 비어 있지 않고 중복 없음. 집합·문자열은 거부 |
| 연결 프로세스 | 1~20개, 각각 올바른 `*.exe` 파일 이름(Windows 파일 이름에 못 쓰는 글자·제어 문자·앞뒤 공백 금지, 255자 이하). 대소문자 무시 중복 금지. `.tmp` 같은 설치 도구 프로세스는 연결 대상이 아니다 |
| 기록 여부 | 호출부(hub)가 기록된 프로세스 목록을 주면, 그 목록에 **정확히** 있는 이름만 받는다(기록된 적 없는 이름을 연결해 달성률이 영원히 0이 되는 일 방지) |
| 개수 | 목표는 20개까지 |
| 수정 | 통째로 교체(PUT). 일부 칸만 바꾸는 입력은 받지 않는다 |

**한 프로세스는 하나의 목표에만** 연결된다. 같은 프로세스가 두 목표에 있으면 같은 활성 시간이 두 번
세어져 총합이 부풀려지기 때문이다. 검증이 먼저 막고, `UNIQUE (kind, name_key)` 제약이 마지막 방어선이다.
비교 키는 `casefold`라서 `Code.exe`와 `code.exe`는 같은 프로세스다(Windows 파일 이름은 대소문자를 구분하지
않는다).

## 하루 스냅샷

목표를 나중에 바꿔도 **지난 날의 달성률이 바뀌지 않게** 날짜별로 그날의 설정(이름, 목표 시간, 연결
프로세스)을 기록한다. 규칙은 단순하다.

- `snapshot_today(today)`가 그날 요일에 적용되는 목표만 현재 설정으로 기록하고, 오늘 안에서는 목표를
  고칠 때마다 다시 호출해 덮어쓴다.
- 날짜가 지나면 이 함수가 그날을 더는 건드리지 않아 확정된다(지난·미래 날짜는 받지 않는다).
- 목표를 삭제해도 지난 스냅샷은 남는다(`goal_id`는 목표 테이블에 묶지 않는다).
- "오늘"은 호출부가 **로컬 시간대**로 정해 넘긴다 — 이 패키지는 시간대를 모른다(`period`와 같은 원칙).

## 아직 없는 것

- 달성 시간 계산(연결 프로세스의 활성 시간 합): `aggregation`에 둘 예정이다. 정의는 활성(active) 시간만
  센다(유휴·백그라운드 제외).
- hub API, UI 화면, 서버로 보내는 계약.
