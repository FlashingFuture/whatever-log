# 목표 동기화 설계 (로그인 사용자)

로그인하면 **목표(이름·하루 목표량·요일)** 를 서버에 두고, 여러 기기가 각자 **그날의 달성 시간** 을 서버로 보낸다.
**목표와 프로세스·사이트의 연결은 이 PC에만** 있고 서버로 가지 않는다. 로그인하지 않으면 지금처럼 모든 것이
로컬에서 돈다(`docs/auth-design.md`, `docs/data-handling.md`). 이 PC 쪽 구조는 `docs/sync-client.md`에 있다.

## 결정

| 주제 | 결정 | 이유 |
| --- | --- | --- |
| 서버가 아는 것 | 목표 이름, 하루 목표 시간, 요일, (기기·날짜·목표별) 달성 분 | 다기기 달성도와 보고서에 필요한 최소한 |
| 서버가 모르는 것 | 연결된 프로세스·사이트, 틱, 창·페이지 제목, URL, 시각 | 기존 약속 유지. 연결은 기기마다 다를 수 있다(모바일은 앱 이름이 다르다) |
| 목표 ID | 클라이언트가 만든 UUID v4 | 오프라인에서 만들고 나중에 올릴 수 있고, 기기 간 같은 목표를 가리킨다 |
| 달성도 저장 | **기기마다 따로 한 줄**(목표, 기기, 날짜) | 각 기기는 자기 줄만 쓰므로 동기화 충돌이 없다. 서버가 합산한다 |
| 합산 | 기기별 분의 합 | PC와 폰을 동시에 쓰면 겹쳐 세어질 수 있다(아래 한계) |
| 지난 날의 목표량 | 달성 줄에 그날의 목표량을 함께 둔다 | 목표를 나중에 바꿔도 지난 날 달성률이 바뀌지 않게(로컬 `GoalSnapshot`과 같은 원칙) |
| 목표 수정 충돌 | `revision` 낙관적 잠금. 다르면 409와 서버의 현재 값 | 두 기기가 동시에 고쳐도 한쪽이 조용히 덮어쓰이지 않는다 |
| 목표 삭제 | 삭제 표시만 남기고(이름은 지움) 그 목표의 달성 줄은 즉시 삭제. 30일 뒤 표시도 정리 | 다른 기기가 삭제를 알아야 한다. 데이터는 최소로 |
| 기기 ID | 기기가 처음 만든 무작위 UUID | 하드웨어 값(MAC, 시리얼, PC 이름)을 쓰지 않는다. 기기 삭제 API로 줄을 지울 수 있다 |

## 한계 (사용자에게도 알린다)

- 두 기기를 **같은 시간에** 쓰면 합산이 실제보다 커진다. "기기별 활성 시간의 합"이라는 정의 그대로다.
- 목표 **이름은 사용자가 쓴 글** 이다. "디스코드 1시간"처럼 쓰면 그 내용이 서버에 간다 — 이름 입력 화면에서 알린다.
- 서버는 날짜별 분만 안다(몇 시에 했는지, 어떤 앱인지는 모른다).
- 계정 삭제 API(`DELETE /account`)로 사용자 데이터를 모두 지울 수 있다.

## 클라이언트 (이 PC 쪽)

이 PC에서 서버로 맞추는 쪽의 구조(구성 요소, `goals.db` 스키마 3, 로그인 직후의 선택, 주기 동기화와 충돌 처리, 에이전트, 화면, 시험,
컨테이너 서버)는 **[docs/sync-client.md](sync-client.md)** 에 있다. 이 문서는 서버에 무엇을 두는지(결정)와 서버 API만 다룬다.

## 서버 API (`apps/server`)

모두 `Authorization: Bearer <토큰>`이 필요하다(없거나 만료면 401). 응답은 `Cache-Control: no-store`.

| 요청 | 설명 |
| --- | --- |
| `GET /goals` | 내 목표 전부(삭제 표시 포함). 목표는 최대 20개라 페이지가 없다 |
| `PUT /goals/{id}` | 목표 만들기·수정. `{name, daily_target_minutes, weekdays, base_revision}`. 새 목표는 `base_revision: 0`, 수정은 현재 revision. 같은 내용으로 처음 만드는 요청을 다시 보내도 200(재시도 안전). revision 불일치·삭제된 목표·이름 중복·20개 초과는 409 |
| `DELETE /goals/{id}` | 목표 삭제(그 목표의 달성 줄도 삭제). 이미 삭제됐으면 204 |
| `PUT /progress` | `{device_id, entries: [{goal_id, day, minutes, target_minutes}]}` 최대 50개를 이 기기의 줄로 덮어쓴다. 없는(삭제된) 목표는 `ignored_goal_ids`로 돌려준다. 기기는 사용자당 10대까지 |
| `GET /progress?from=&to=` | 날짜 구간(최대 400일)의 목표·날짜별 합산: `{goal_id, day, minutes, target_minutes, percent, devices}` |
| `DELETE /devices/{device_id}` | 그 기기가 보낸 달성 줄을 모두 삭제 |
| `POST /auth/logout` | 이 토큰을 서버에서 폐기(204) |
| `DELETE /account` | 사용자와 목표·달성·토큰을 모두 삭제(204). 되돌릴 수 없다 |

## 비용 (Cloudflare 무료 한도 기준, 도입 전 요금 페이지 재확인)

- 사용자 1명이 1년 동안 쌓는 달성 줄은 (목표 5개 × 기기 2대 × 365일) ≈ 3,650행으로 작다.
- 요청마다 D1 읽기 1~2회(토큰 확인). 동기화는 변경이 있을 때만 하고 한 번에 50줄을 묶어 보내 쓰기 횟수를 줄인다.
- 아직 없는 것: 요청 속도 제한. 사용자가 늘면 Cloudflare 규칙으로 로그인·쓰기 경로를 제한한다.
