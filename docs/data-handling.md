# 내 데이터는 어떻게 다뤄지나요?

whatever.log가 어떤 데이터를 모으고, 어디에 두고, 무엇을 밖으로 보내는지 알려 드려요.
먼저 한 줄로 요약하면 이렇습니다.

> **기록은 이 PC 안에만 있어요. 로그인하면 목표 달성률(목표 이름·목표 시간·달성 시간)만 서버로 가고,
> 어떤 프로그램이나 사이트를 썼는지는 이 PC 밖으로 나가지 않아요.**

## 한눈에 보기

| | 로그인 안 함 | 로그인함 |
| --- | --- | --- |
| 쓴 프로그램·사이트 기록 | 이 PC에만 있어요 | 이 PC에만 있어요 |
| 목표와 연결한 프로그램·사이트 | 이 PC에만 있어요 | 이 PC에만 있어요 |
| 목표 이름·목표 시간·요일 | 이 PC에만 있어요 | 서버에도 저장돼요 |
| 날짜별 달성 시간 | 이 PC에서 계산해요 | 서버에도 보내요 |
| 이메일 주소 | 가지 않아요 | 계정을 구분하려고 서버에 저장돼요 |
| 기록·집계·목표 기능 | 모두 쓸 수 있어요 | 모두 쓸 수 있어요 |

**어떤 경우에도 서버로 가지 않는 것:** 프로세스 이름, 실행 파일 경로, 사이트 도메인, 아이콘, 시각별 기록,
창 제목, 페이지 제목, URL, 키보드 입력, 화면 내용.

> **지금 어디까지 만들어졌나요?** 로그인(Google), 서버의 목표·달성도 저장, 이 PC에서 목표와 달성도를 서버로 보내는
> 동기화(로그인 직후 어떤 목표를 올릴지 고르는 확인 창 포함)까지 코드로는 만들어져 있어요. 다만 서버가 아직 배포되기 전이라
> **지금 실제로 서버에 저장되는 건 이메일 주소, Google 계정을 구분하는 값, 이 앱의 로그인 토큰의 해시뿐**이에요. 목표 이름 등은 **확인 창에서 직접
> 체크한 것만** 올라가고, 동기화 에이전트를 실행해야 이후 수정과 달성 시간이 반영돼요. 계획이 바뀌면 이 문서를 먼저 고쳐요.

## 자주 묻는 질문

### 로그인하지 않아도 쓸 수 있나요?

네. 기록, 집계, 목표 관리는 로그인과 상관없이 항상 동작해요. 로그인은 여러 기기에서 같은 목표를 쓰거나
보고서를 받고 싶을 때만 필요해요. 로그인하지 않으면 아무것도 서버로 가지 않아요.

### 로그인하면 정확히 무엇이 서버로 가나요?

| 항목 | 예 | 설명 |
| --- | --- | --- |
| 목표 이름 | `공부`, `업무` | 내가 직접 만든 목표의 이름 |
| 목표 시간·요일 | `120분`, 월~금 | 내가 그 목표에 정한 값 |
| 날짜 | `2026-11-05` | 어느 날의 달성도인지(몇 시인지는 보내지 않아요) |
| 달성 시간 | `95분` | 그 목표에 연결한 활동의 활성 시간 합(기기별로 따로 보내요) |
| 그날의 목표 시간 | `120분` | 목표를 나중에 바꿔도 지난 날 달성률이 바뀌지 않게 |
| 기기 ID | 무작위 번호 | 기기를 구분하는 값이에요. PC 이름이나 하드웨어 번호가 아니에요 |

달성률(`79%`)은 서버가 달성 시간과 목표 시간으로 계산해요.

### 서버가 내가 어떤 앱이나 사이트를 썼는지 알 수 있나요?

아니요. 어떤 프로그램·사이트를 어떤 목표에 연결했는지는 이 PC에서만 정하고, 그 연결 자체를 서버로 보내지
않아요. 서버가 받는 건 "공부 목표 120분 중 95분(79%)"까지예요. 그 95분이 어디서 나왔는지는 알 수 없어요.
서버 데이터베이스에는 프로세스·사이트 이름을 담을 칸 자체가 없고, 테스트로 이 칸 구성을 고정해 두었어요.

### 목표 이름도 서버에 저장되나요?

네. 목표 이름은 내가 쓴 글이라 **서버에 그대로 저장돼요.** "디스코드 1시간"처럼 쓰면 그 내용이 서버에 가니,
알리고 싶지 않은 내용은 목표 이름에 쓰지 마세요.

### 두 기기를 동시에 쓰면 어떻게 되나요?

기기마다 자기 달성 시간을 따로 보내고, 서버가 합산해요. 그래서 PC와 휴대폰을 **같은 시간에** 쓰면 합계가
실제보다 커질 수 있어요.

### 로그인하는 동안에는 무엇이 오가나요?

로그인 창에서 Google 계정을 고르면, Google이 이 앱에 일회용 인증 코드를 주고 앱이 그 코드를 우리 서버에 보내 로그인을 마쳐요.
Google 비밀번호는 이 앱도 서버도 보지 못하고, 서버는 **이메일 주소, Google 계정을 구분하는 값, 이 앱이 쓸 로그인 토큰의 해시**만 저장해요(요청하는 정보는 이메일뿐이에요). 토큰 원본은 서버에 남기지 않고 이 PC의 자격 증명 관리자에만 있어요.

### 로그아웃하면 서버의 데이터는 어떻게 되나요?

로그아웃은 이 PC의 로그인 정보를 지우고, 서버에서도 로그인 토큰을 폐기해요(서버에 닿지 못하면 이 PC에서만
로그아웃돼요). **이미 서버에 올라간 목표와 달성도는 남아요.** 지우려면 아래 "데이터를 지우려면"을 보세요.

### 로그인 정보는 어디에 저장되나요?

Windows 자격 증명 관리자에만 저장돼요. 기록 파일(`recorder.db`)이나 목표 파일(`goals.db`)에는 넣지 않아서,
기록 파일을 복사하거나 백업해도 로그인 정보가 따라가지 않아요. 안전한 저장소가 없는 환경에서는 로그인 정보를
평문 파일로 남기지 않고 로그인을 거부해요.

## 데이터를 지우려면

- **기록:** `apps/recorder/recorder.db`(와 같은 이름의 `-wal`, `-shm` 파일)를 삭제하면 모든 기록이 사라져요.
  recorder를 먼저 종료하세요.
- **목표와 하루 스냅샷:** `goals.db`(와 같은 이름의 `-wal`, `-shm` 파일)를 삭제하면 목표와 지난 스냅샷이 모두
  사라져요. 목표를 쓰는 프로그램(hub, 앱)과 **동기화 에이전트(`apps/sync`)를 먼저 종료하세요.** 에이전트가 열어 둔 상태면
  Windows에서 파일이 지워지지 않을 수 있고, 로그인한 채로 두면 지운 뒤 다음 주기에 빈 `goals.db`가 다시 만들어질 수 있어요.
  이 PC의 파일만 지워지고 **서버에 올라간 목표는 그대로예요**(서버의 데이터는 아래 항목으로 지워요).
- **아이콘 캐시:** `apps/hub/icon-cache/` 폴더를 삭제하면 다음에 다시 만들어요.
- **서버의 데이터:**
  - 목표를 지우면 이름은 바로 지워지고, 다른 기기가 삭제를 알 수 있게 삭제 표시만 30일 남아요. 그 목표의 달성
    기록은 바로 지워져요.
  - 기기를 지우면 그 기기가 보낸 달성 기록이 모두 지워져요.
  - 계정을 삭제하면 이메일, 목표, 달성 기록, 로그인 토큰이 한 번에 지워져요. 서버 쪽 기능(`DELETE /account`)은
    만들어져 있지만 **화면의 버튼은 아직 없어요.** 그 전에 삭제가 필요하면 운영자에게 요청해 주세요.

# 개발 메모

여기부터는 구현하는 사람을 위한 내용이에요. 위의 약속(무엇이 저장되고 무엇이 나가는지)이 코드에서 어떻게
지켜지는지, 그리고 정확도·보안과 관련해 고민한 내용을 적었어요.

## 문서를 고치는 규칙

- "준비 중/예정"은 아직 구현되지 않은 계획이에요. 구현되면 표시를 지우고, 계획이 바뀌면 이 문서를 먼저 고쳐요.
- 서버에 새 데이터를 더하거나 외부로 보내는 값을 바꿀 때는, 구현 전에 위 표와 보관·삭제 정책을 먼저 고치고 그
  내용과 구현이 일치하는지 확인해요.
- 화면의 로그인 안내 문구(`apps/ui/src/components/account/AccountMenu.ts`)는 이 문서의 요약이에요. 둘이 어긋나지
  않게 같이 고쳐요.

## 이 PC 안에서만 오가는 데이터

아래 데이터는 이 PC의 로컬 DB(`recorder.db`)와 로컬 캐시에만 있고 어떤 외부 서비스로도 보내지 않아요.

| 데이터 | 언제 모으나 | 어디에 두나 | 용도 |
| --- | --- | --- | --- |
| 포그라운드 프로세스 이름 | 15초마다 | `recorder.db` | 활성 시간 집계 |
| 창이 떠 있는 프로세스 목록 | 15초마다 | `recorder.db` | 유휴·백그라운드 시간 집계 |
| 마지막 입력 후 경과 시간 | 15초마다 | `recorder.db` | 활성/유휴 판정 (키 입력 내용은 기록하지 않음) |
| 실행 파일 경로 | 프로세스를 처음 볼 때 | `recorder.db` | 프로세스 아이콘 추출 |
| 프로세스 아이콘 | 화면에 처음 표시할 때 | `apps/hub/icon-cache/` | 화면 표시 (PNG 캐시) |
| 활성 사이트 도메인 | 지원하는 브라우저가 포그라운드일 때 15초마다 | `recorder.db` | 사이트별 사용 시간 |
| 사이트 아이콘 | 화면에 표시할 때 | 저장하지 않음(hub 메모리에만 잠시) | 화면 표시 |
| 목표(이름·하루 목표 시간·요일)와 연결한 프로세스 | 사용자가 설정할 때 | `goals.db` | 목표 달성 시간 계산. **연결한 프로세스는 서버로 보내지 않음** (설계: `docs/goals-design.md`) |

모으지 않는 것:

- 키보드 입력 내용, 화면 내용(스크린샷), 클립보드
- 페이지 제목, URL의 경로·쿼리·해시 (사이트는 **도메인까지만** 저장)
- 지원하는 브라우저가 아닌 앱의 창 제목 (창 제목은 지원하는 브라우저가 포그라운드일 때만 읽음)

### 사이트 정보를 얻는 방법

지원하는 브라우저(Chromium 계열: **Chrome, Edge, Brave, Vivaldi**)가 포그라운드일 때 창
제목으로 방금 본 페이지를 찾아 도메인만 뽑는다. Firefox, Opera 등은 지원하지 않는다. 이
과정에서 그 브라우저의 방문 기록을 **읽기 전용 복사본으로만** 읽고, 원본은 건드리지 않는다. 복사본은
임시 폴더에 두었다가 recorder가 종료될 때 지우고(비정상 종료로 남았으면 다음 실행 때 지운다.
다른 프로세스가 쓰는 폴더는 지우지 않는다),
읽은 내용 중 도메인만 남기고 나머지(제목·경로)는 저장하지 않고 버린다. 브라우저 확장
프로그램은 설치하지 않는다.

이 방식은 **추정**이다. 같은 제목의 다른 사이트(새 탭 등)나 방문 기록에 아직 없는 페이지는
틀리거나 도메인 없이(없음) 기록될 수 있다. **시크릿(InPrivate) 창은 주의가 필요하다** —
시크릿 창에서 본 페이지는 브라우저의 방문 기록에 남지 않아 대개 도메인 없이 기록되지만, 창
제목에는 시크릿 표시가 없어서 같은 제목의 페이지를 일반 창에서 방문한 적이 있으면 그 사이트의
도메인이 기록될 수 있다(둘을 구분하지 못한다). 얼마나 맞는지 보려고 recorder 로그에 "브라우저가
포그라운드였던 틱 수 / 도메인을 찾은 틱 수"만 남긴다(도메인·제목은 로그에 남기지 않는다).

### 사이트 아이콘

브라우저가 이미 저장해 둔 아이콘(설치된 브라우저들의 프로필에 있는 `Favicons`)을 읽기 전용
복사본으로 읽어 화면에 보여 준다(복사본은 읽고 바로 지우고, 비정상 종료로 남았으면 hub가
다시 시작할 때 지운다). **사이트로 요청을 보내지 않고**, 제3자 아이콘 서비스도 쓰지 않으므로
외부 네트워크 요청이 없다. 아이콘은 디스크에 따로 저장하지 않고 hub 메모리에만 **최대 10분**
둔다(화면의 브라우저 캐시도 같은 시간만 유지한다). **이것은 아이콘에 대한 이야기일 뿐이다.** 브라우저의 방문 기록을
지워도 `recorder.db`에 이미 저장된 사이트 도메인과 사용 시간은 남는다(이 앱이 방문 기록의 복사본에서 도메인만 뽑아 따로
저장한 것이라서). 사이트 흔적을 이 PC에서 없애려면 "데이터를 지우려면"의 `recorder.db` 삭제가 필요하다.
브라우저에 아이콘이 없는 사이트는 도메인 첫 글자로 대신 표시한다. 기록된(recorder가
저장한) 도메인에 대해서만 아이콘을 찾고, 이 앱의 화면(UI)에서 온 요청에만 응답한다. 방문 중인
다른 웹페이지가 아이콘 주소를 불러 보고 어떤 사이트가 기록돼 있는지 알아내지 못하게 하려는
것이다(프로세스 아이콘도 같다).

## 서버로 나가는 데이터 (구현 현황과 설계)

기록에서 나온 값이 밖으로 나가는 경로는 로그인한 사용자의 두 가지뿐이다. 전 틱(15초 단위 기록)이나 프로세스·사이트 이름은
보내지 않고, 이 PC에서 **마스킹·집계한 값만** 보낸다. 그와 별도로 **로그인하는 과정 자체**에서도 값이 오간다(아래).

1. **목표 동기화** — 여러 기기에서 같은 목표를 쓰고, 기기마다 날짜별 달성 시간을 서버로 모은다
   (설계: `docs/sync-design.md`, 이 PC 쪽 구조: `docs/sync-client.md`).
2. **AI 보고서 생성(예정)** — 사용자가 요청할 때만 위 값으로 보고서를 만든다.

### 로그인하는 동안 서버로 가는 값

로그인이 끝나기 전에도 이 PC는 우리 서버(`POST /auth/google`)에 **Google이 돌려준 인증 코드, 코드 교환용 비밀값(PKCE
verifier), 로그인 후 돌아올 주소(`127.0.0.1`의 임시 포트)** 를 보낸다. 서버가 그것으로 Google과 코드를 교환하고(클라이언트 비밀은 서버에만
있다), 우리 토큰을 돌려준다. 서버는 **이메일 주소, Google 계정 고유 값(`sub`), 우리 로그인 토큰의 SHA-256 해시만** 저장하고(토큰 원본과 Google의 토큰은 보관하지 않는다) 로그에
코드·토큰을 남기지 않는다. 요청은 다른 주소로 리디렉션되어도 따라가지 않는다(토큰·코드가 다른 출처로 새지 않게). 요청하는 범위는
`openid email`뿐이다.

| 부분 | 상태 |
| --- | --- |
| Google 로그인(데스크톱 → 서버), 화면의 로그인·로그아웃 버튼 | 구현됨 |
| 로그아웃 때 서버 토큰 폐기 | 구현됨, 서버 배포 후 동작(그 전에는 이 PC에서만 로그아웃) |
| 서버의 목표·달성도·기기·계정 삭제 API | 구현됨, 배포 전 |
| 이 PC에서 목표·달성도를 서버로 보내는 동기화 클라이언트(`apps/sync`)와 확인 창 | 구현됨, 서버 배포 후 동작. 에이전트는 직접 실행해야 함 |
| 로그인 직후 "어떤 목표를 올릴지" 고르기(올리지 않은 목표는 이 PC에만 남음) | 구현됨 |
| 화면의 계정 삭제 버튼, 기기 목록 | 예정 |
| AI 보고서·메일 | 예정 |

### 서버에 저장되는 칸

- 사용자: 이메일, Google 사용자 고유 값(`sub`). 로그인 토큰은 해시만 저장하고 원문은 저장하지 않는다.
- 목표: 이름, 목표 시간, 요일, 변경 번호(`revision`), 삭제 표시. **프로세스·사이트 칸은 없다.**
- 달성도: (목표, 기기, 날짜)별 달성 분과 그날의 목표 분. **시각 칸은 없다.**

`apps/server/tests/syncProgress.test.ts`가 `goals`·`progress` 테이블의 칸 구성을 고정해, 프로세스·사이트·기기
이름 같은 칸이 나중에 몰래 추가되지 않게 한다.

### 로그인과 로컬 기능의 경계

로그인이 없어도, 그리고 로그인 기능 자체가 깨져도 기록·집계·목표는 동작해야 한다. 이를 코드 구조로
강제한다(`packages/cloud/tests/test_isolation.py`).

- 서버와 통신하는 코드는 `packages/cloud`에만 있다. recorder·집계·목표·크롬 스냅샷은 `cloud`를 import하거나
  의존하지 않는다.
- 화면의 로그인 버튼 때문에 hub만 예외이고, hub가 `cloud`를 아는 곳은 어댑터 파일
  `apps/hub/src/hub/cloud_adapter.py` 하나뿐이며 import는 함수 안에서만 한다. `cloud`를 불러오지 못하면
  계정 기능만 "사용할 수 없음"이 되고 hub의 나머지는 그대로 뜬다.
- 로그인 토큰은 hub와 화면을 지나가지 않는다. 화면이 받는 로그인 상태에는 이메일만 있다.
- 자세한 내용은 `docs/auth-design.md`, 화면의 상태 관리는 `docs/ui-state.md`를 본다.

## 정리해 둘 것

- 서버의 요청 횟수 제한은 아직 없다. 사용자가 늘면 로그인·쓰기 경로에 제한을 건다.
- 서버에 새 데이터(보고서 등)를 더할 때의 보관·삭제 정책은 구현할 때 이 문서에 추가한다.
